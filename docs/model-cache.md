# OPFS によるモデルキャッシュ

状態: 実装を追加。Node.js の模擬 OPFS テストで挙動を確認する。OPFS を使うブラウザーでの保存・再読込・推論の手動確認は未実施。

## 保存と復元

- モデルの取得時に Response のストリームを OPFS へ書き出し、同時に受信サイズと SHA-256 を検証する。モデル全体を一つの ArrayBuffer や Blob にしてから保存しない。
- サイズとハッシュが固定モデル定義に一致した後に、検証済みファイル名を指すメタデータを確定する。未完了または未参照のファイルは次回起動時に掃除する。
- OPFS 内の専用ディレクトリにモデルと管理情報を置く。管理情報には形式バージョン、リポジトリ・revision・ファイル名・SHA-256 を含むモデル識別子、サイズ、最終使用時刻を含め、モデル定義と異なるキャッシュは再利用しない。
- 起動時に期限とファイルのサイズ・SHA-256 を検証する。有効なキャッシュは「モデルを取得」操作を必要とせずロードに使える。キャッシュ確認だけでネットワーク取得や推論は開始しない。
- ロード直前にも保持期限・サイズ・SHA-256 を再確認し、期限切れや破損を検出したデータは削除して再取得を促す。

## 保持期間と削除

初期値は最終使用から7日。画面から1〜30日の整数で変更できる。最後に保存した時、モデルのロードに成功した時、翻訳に成功した時に最終使用時刻を更新する。ページを開くだけでは保持期間を延長しない。期限切れは起動時またはロード前の確認時に処理するため、期限ちょうどにページを開いていない場合の即時削除は保証しない。

サイトの OPFS 領域にはブラウザーの容量上限があり、ブラウザーの利用者や OS によって削除される場合もある。アプリは永続ストレージを要求しない。設定ファイルには保持日数だけを保存し、モデル本体は OPFS に置く。サイトデータを消去するとキャッシュも失われる。

複数タブからの読み書きは [Web Locks API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API) で調整する。モデルをロードして使うタブは共有ロックを保持し、削除・置換は排他ロックを使うため、他タブが利用中のモデルは使用終了まで削除できない。ロックは同一オリジン内のアプリ操作を調整するもので、ブラウザーや OS が領域を消去することまでは防がない。

OPFS は [File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system) のサイト専用領域を使う。永続性やアプリ本体のオフライン配信を保証しない。

## 保存先を選ぶ

初期の保存先は「このブラウザーに保存（推奨）」。OPFS 非対応、容量不足、または保存エラーの場合は説明を表示し、利用者が「このページのメモリだけに保存」を選んで取得を再試行できる。失敗した取得を裏で再取得することはない。メモリ保存は従来の方式で、このタブを再読み込み・終了するとデータを失う。

## API とファイル

推論 API は引き続き Blob / File を受け取る。OPFS の取得・検証・保持期限・削除はアプリ側の `ModelCache` と `ModelDownloader` が管理する。wllama 固有の API はストレージ層に公開しない。

| ファイル | 責務 |
| --- | --- |
| `src/storage/model-cache.ts` | 専用 OPFS 領域、モデル検証、保持情報、使用リース、期限、設定 |
| `src/models/download.ts` | 固定 URL への取得と、メモリ保存用のストリーム検証 |
| `src/models/model-download.ts` | OPFS / メモリの選択、状態・進捗・中止・削除 |
| `src/poc/translation-session.ts` | ロード中の使用リース、成功したロード・翻訳後の最終使用時刻更新 |
| `src/ui/model-download.ts` | 保存先・期限・キャッシュ状態と操作の表示 |
| `tests/model-cache.test.mjs` | 模擬 OPFS を用いたストレージ処理テスト |

## 手動ブラウザー確認

自動テストは模擬 OPFS を使うため、実際のブラウザー実装や実モデルの推論を証明しない。OPFS 対応ブラウザーの HTTPS または localhost で次を確認し、ブラウザー・バージョン、OS、各結果、エラーを記録する。

1. OPFS 保存を選び、固定モデルの取得と整合性検証を完了する。開発者ツールのネットワークで Hugging Face への一度の要求と、その後に推論 API がモデルをロードできることを確認する。
2. ページを再読み込みする。キャッシュ済み表示になり、モデルを再取得せずにロードと1文翻訳ができることを確認する。
3. 保持期間の初期値7日、1日・30日への変更、範囲外の値の拒否を確認する。テスト用に期限を過去へ進めた場合、起動時またはロード前にキャッシュが削除され再取得を促すことを確認する。
4. キャッシュ削除後に状態が未取得へ戻り、再度取得できることを確認する。モデルのロード中は削除できないことも確認する。
5. 取得中止、ページの途中終了、同サイズの破損、サイズ不一致を再現する。部分ファイルが再利用されず、次回の確認で掃除され、有効なキャッシュだけがロードされることを確認する。
6. ストレージ容量不足を模擬または再現し、エラーの説明を確認する。メモリ保存を選んだ場合のみ取得が再試行され、再読み込みでモデルが失われることを確認する。
7. 2つのタブで同じアプリを開く。一方がモデルをロード中に他方から削除しようとした場合、使用中のモデルが削除されず、ロード解除後に削除できることを確認する。
8. OPFS 非対応または利用不可の環境で、メモリ保存を選択して従来の取得・ロード経路を利用できることを確認する。

この手動確認が終わるまでは、OPFS による実ブラウザーの保存・再利用、実モデルのロード・翻訳は未検証として扱う。モデルキャッシュはアプリのオフライン化を意味しない。アプリ本体や wllama の WASM / Worker の配信にはネットワークが必要な場合がある。
