# 通常の翻訳画面 UI 設計

## 目的と利用者

日本語と英語の短い文章を、モデルの準備から翻訳、結果のコピーまでこのページで完了できる画面にする。主な利用者は初めて使う人と、翻訳のために繰り返し開く人。翻訳を主役にし、モデルや保存先の設定は必要になったときに見つけられるようにする。

このアプリが行うのは端末内での推論。初回はアプリ資産とモデルの取得にネットワークが必要だが、Service Worker で現在のアプリ資産を保存し、期限内で検証済みのモデルを OPFS に保存した場合は、次回以降ネットワーク接続なしで起動できる。オフライン時もモデルロードは利用者が明示する。入力文や翻訳結果を永続保存しない。新しいライブラリ、UI フレームワーク、外部フォント、画像、翻訳 API は導入しない。

設計の判断にはデザイン批評スキルの H1（状態の可視性）、H2（利用者の言葉）、H3（操作の取り消し）、H5（誤操作の防止）、H6（認識しやすさ）、H8（不要な要素を減らす）、H9（回復可能なエラー）、Fitts の法則、Progressive Disclosure を適用する。

## 画面構成と優先順位

1. **簡潔なヘッダー** — 製品名「local-web-translation」と「翻訳の実行は端末内で行います。初回はモデルを取得します。」を示す。プライバシーの説明とモデル取得に必要な通信を混同させない。
2. **翻訳の状態** — 翻訳画面の近くに常時表示する。見出しで「翻訳できます」「文章の入力待ち」「入力を確認してください」「モデルのロードが必要です」など、今翻訳できるかを明示する。取得・ロード・翻訳中や回復が必要なときも短い見出しで状態を示し、進捗や次の操作は本文に置く。モデルの取得・ロードは自動で始めない。
3. **翻訳ワークスペース** — デスクトップでは入力と結果を横並びにする。言語方向の操作は両欄の上に、翻訳ボタンは入力欄の近くに置く。狭い画面では入力、翻訳ボタン、結果の順に縦積みにする。
4. **オフライン利用と設定** — ワークスペースの後、既存のモデル設定と sibling になる独立した折りたたみ「オフライン利用と設定」を置く。翻訳の近くにはオフライン可否の短い要約だけを表示し、資産保存、更新、アプリデータ削除は詳細内にまとめる。言語方向と backend の設定保存状況は翻訳元・翻訳先欄の近くで説明する。
5. **モデルと保存設定** — ワークスペースの後に折りたたみ可能な「モデルと保存設定」として置く。モデルの取得、保存先、保持期間、ロード時の実行設定、ロード解除、モデルデータ削除をまとめる。エラー回復に必要な操作は、この折りたたみ領域だけに隠さず、翻訳の状態領域から開いて該当操作へ移動できるようにする。
6. **詳細ログ** — 取得・推論・ストレージの診断情報を別の折りたたみ領域に置く。通常の翻訳を妨げず、エラー時の案内から開ける。通常の操作ログには入力文や翻訳文を記録しない。エラー詳細に内容が含まれる場合があるため、共有前の確認を案内する。

## 翻訳ワークスペースの要素

### 言語方向

- 「翻訳元」「翻訳先」のネイティブな選択欄を用意し、日本語と英語だけを選択できるようにする。初期値は日本語 → 英語。
- 2 欄が同じ言語にならないようにする。片方を変更したときは、もう片方に変更前の反対側の値を移す。翻訳元・翻訳先の表示ラベルから方向が分かるようにする。
- 「翻訳方向を入れ替え」ボタンは言語だけを交換し、入力文を保持する。方向の変更ではモデルを再ロードしない。
- 翻訳元・翻訳先の対向する方向と backend の要求値だけを次回起動時の設定として保存する。保存状態や保存失敗の案内は言語欄の近くに置く。保存できなくてもこのページでの翻訳を続けられる。
- 翻訳方向と実行設定の保存は「モデルと保存設定」内のチェックボックスで切り替え、既定はオンとする。オフにすると保存済み方向と backend を削除し、現在のページの選択は保つ。次回は既定値を使う。入力文と翻訳結果は保存しない。
- 入力言語、翻訳先言語、または入力文が変わったら、前の結果、コピー完了表示、翻訳時間を消す。古い結果を新しい方向・入力の結果と誤認させない。
- 翻訳中は言語欄を無効化する。

### 入力欄

- 初期表示は空欄。入力例は翻訳方向に対応した「例文を入力」操作で入れる。入力が空でない間は操作を無効にし、「入力を消去してから使えます」と理由を表示する。入力を黙って上書きしない。
- 見えるラベルを付け、`maxlength="10000"` を設定する。10,000 UTF-16 コード単位の制限と残りを `現在数 / 10000` で表示する。カウンターは毎キー入力を支援技術に読み上げさせない。上限を超える入力は受け付けず、補助文にも上限を記す。
- 入力欄は `textarea` とし、入力言語に合わせて `lang` を更新する。スペルチェックを有効にする。プレースホルダーは操作例ではなく短い入力案内に使う。
- 「入力を消去」はページ内だけに最後の消去内容を保持し、消去直後に「元に戻す」を表示する。入力が空の間だけ元に戻せる。新しい文字や例文を入力したら退避内容を破棄する。入力文を `localStorage` 等に保存しない。
- 「Ctrl/Cmd + Enter で翻訳」と見える位置に案内する。ショートカットはボタンと同じ利用条件に従い、IME の変換中 (`isComposing`) は実行しない。

### 翻訳操作と出力

- 「翻訳する」を唯一の主ボタンにする。モデル未取得・未ロード、入力が空、10,000 UTF-16 コード単位超過、モデル取得処理中、他の推論処理中は実行できない状態にし、ボタンの近くに該当理由と次の操作を表示する。
- 翻訳開始時に前の出力、コピー表示、計測時間を無効化する。処理中は入力を読み取り専用、言語欄と競合するモデル操作を無効化し、受信した文章を出力欄に累積表示して「翻訳中」と「処理を中止」を表示する。生成中の暫定結果はコピーできない。完了または停止後に保持した部分結果は選択・コピーできる。
- 出力欄には見える見出し「翻訳結果」と、翻訳元・翻訳先言語を示す。結果は自動読み上げしない。結果文字列は選択可能な通常テキストにして、長文でも折り返す。
- 結果が空なら「翻訳結果はここに表示されます」と案内する。翻訳完了後に出力が空だった場合は、未実行の空状態と区別して、その状態と回復案内を表示する。
- 出力がトークン上限で切れた場合は部分結果を表示し、結果を選択・コピーできる状態を保つ。結果の近くに「上限に達したため、途中で切れている可能性があります。文を分けて再度翻訳してください」と表示する。
- 「結果をコピー」は出力がある場合だけ有効にする。`navigator.clipboard.writeText` の成功・失敗を画面内で示す。失敗時も出力を選択できるようにし、「コピーできませんでした。結果を選択してコピーしてください」と案内する。コピー要求中に入力や方向が変わった場合、古い要求の成功・失敗を新しい画面状態に表示しない。

## モデルと保存設定

- 初回取得前にモデル名、配信元、PLaMo Community License、取得サイズ約 573 MB を示す。利用者が明示的に「モデルを取得」を押してから通信を始める。
- 取得・検証中は読み込み量、全体量、割合を表示する。中止できる段階では中止ボタンを示し、失敗時は再試行と保存先の選択を案内する。進捗を頻繁に読み上げ続けない。
- 保存先は「このブラウザーに保存（推奨）」と「このページのメモリだけに保存」。前者はブラウザーのサイトデータから消える場合があること、後者はページを閉じると保持されないことを説明する。ブラウザーの永続ストレージ許可を求めない。
- ブラウザー保存の保持期間は初期値 7 日、1〜30 日で調整する。「最後に保存・ロード・翻訳した日から数え、ページを開いただけでは延長されない」と明示する。最後の利用日時、モデルサイズ、削除予定日が取得できる場合に表示する。
- 実行設定は「自動選択（WebGPU 優先）」と「CPU（WASM）」を示す。要求設定と実際の環境を別表示する。自動選択では wllama が GPU 使用を報告しないため、実際の環境は「確認できません」とする。CPU は `n_gpu_layers=0` と Worker の WebGPU 無効化が適用されたことを根拠として表示する。GPU 名や使用レイヤー数は、確かな値が取得できない限り表示しない。設定変更はモデル未ロード時のみ可能にし、ロード解除が必要な理由を隣に表示する。
- 保存データの削除はモデルを使用中なら無効化し、「先にロードを解除してください」と表示する。削除ボタンを押すと同じ領域内に対象・再取得が必要になることを示す確認を出し、「削除を確定」「戻る」を選べるようにする。モデル使用中になった場合は確認を無効化して閉じる。
- 読み込み解除はモデルキャッシュを削除しないことを明示する。解除後も入力文と、入力・方向が変わっていない有効な結果を画面に保持する。

## オフライン利用と設定

- オフライン状態の要約は翻訳画面の近くに短く表示し、保存・更新・削除の操作は「オフライン利用と設定」の折りたたみ領域に置く。アプリ資産（CacheStorage）とモデル（OPFS）の状態を別々に示し、両方が揃っていない限りオフライン利用可能とは表示しない。
- 「オフライン利用を準備」は利用者の明示操作で開始する。Service Worker が制御していない初回は、再読み込みによって入力文と結果が失われる説明と確認を先に表示する。更新の適用も明示的な確認後に限り、処理中は無効にする。
- アプリ本体の保存データ削除はモデル削除と分け、busy 中や同じアプリを開く別タブがある場合は開始しない。確認後は app scope の資産キャッシュだけを削除し、OPFS モデルと翻訳設定を残す。
- 詳細な状態、Service Worker の asset/update contract、503 回復画面とオフライン時の復旧手順は[オフライン利用と設定の設計書](offline-and-preferences.md)を参照する。

## 状態と回復

| 状態 | 画面に示す内容 | 次にできること |
|---|---|---|
| キャッシュ確認中 | モデルの保存状態を確認中 | 待つ。取得やロードは自動開始しない |
| 未取得 | 見出し「モデルの取得が必要です」。翻訳には取得とロードが必要 | 保存設定を開き、約 573 MB の取得を開始 |
| 保存済み・未ロード | 見出し「モデルのロードが必要です」 | 「モデルをロード」を実行設定とともに開始 |
| ロード済み・入力なし | 見出し「文章の入力待ち」。モデルはロード済み | 文章を入力 |
| ロード済み・入力エラー | 見出し「入力を確認してください」 | 入力欄の案内に従って修正 |
| ロード済み・有効な入力 | 見出し「翻訳できます」と状態「モデルはロード済みです」 | 翻訳 |
| 取得中・検証中 | 段階と進捗。中止できる場合は中止操作 | 完了を待つか、中止 |
| ロード中 | モデルロード中で初回は時間がかかる場合がある | 待つか、中止 |
| 翻訳中 | 翻訳処理中 | 待つか、中止 |
| ロード解除中 | リソースを解放中。入力と出力は保持 | 完了を待つ |
| 中止処理中 | 停止とリソース解放を待っている状態 | 完了を待つ。二重に中止しない |
| 完了・通常出力 | 翻訳完了、結果、必要なら処理時間 | 結果を確認・コピー。入力変更で結果を消去 |
| 完了・空出力 | 出力が空だったことと詳細ログの案内 | 入力を見直して再翻訳、またはログを開く |
| 出力上限 | 部分結果と切れている可能性 | 部分結果を確認・コピー、文章を分けて再翻訳 |
| エラー・ロード解除が必要 | 見出し「モデルのロード解除が必要です」 | リソースを解放し、必要ならモデルをロードし直す |
| エラー | 起きたこと、平易な原因、具体的な回復操作 | 文の修正、再試行、ロード、モデル取得、ログ確認など原因に対応する操作 |

### エラー時の扱い

- 入力文字数、空欄など利用者が修正できる問題は入力欄の近くで、修正方法とともに知らせる。
- モデル未取得・未ロードは障害として扱わず、モデル取得・ロードへの明確な道筋を示す。
- モデル取得失敗では通信、空き領域、保存先など判別できる理由だけを示し、再試行を提供する。診断情報は折りたたみログから見られる。
- 推論失敗では入力を保持し、再翻訳・モデル再ロード・ログ確認など可能な回復操作をワークスペース上のエラー領域から実行できるようにする。
- ロード解除／リソース解放に失敗した場合、エラーと再試行可能な解除操作を常時見える翻訳の状態領域に出す。設定やログを開かないと解決できない構造にしない。
- 古い完了結果は入力・方向の変更、または新しい翻訳の開始時に破棄する。ロードやロード解除だけでは破棄しない。
- 失敗表示だけで終わらせず、次に安全に取れる行動を必ず添える。技術情報はログへ分離する。

## レスポンシブ、アクセシビリティ、見た目

- 320 px では全体を縦積みにし、ページの横スクロールを発生させない。768 px 以上では入力・結果を横並び、1280 px では読みやすい最大幅を保つ。長い結果・エラー・ログも画面幅を押し広げない。
- 落ち着いた明るい背景、濃紺の本文、青の主操作、白い入力・結果面、控えめな境界線を使う。宣伝用の大きなヒーローや不要な装飾は置かない。本文は 16 px 以上、行間は 1.4〜1.6、本文コントラストは WCAG AA 4.5:1 を基準にする。
- タッチ操作領域は最低 44×44 px。主操作は塗りつぶし、補助操作は控えめなボタンにして、色だけで状態を伝えない。hover と同等に明確なキーボード focus を付ける。
- ネイティブの `select`、`textarea`、`button`、`details/summary` を使い、全コントロールに表示ラベルとキーボード操作を用意する。入力欄の `lang`、関連ヘルプ、文字数制限を支援技術から識別できるようにする。
- 処理段階の変化は `role="status"` で簡潔に伝える。入力ごとのカウンターやダウンロードの細かい進捗値をライブ通知しない。エラーは `role="alert"` で説明し、出力は勝手にフォーカスを移さず、結果見出しのある領域として読みやすくする。
- レイアウトや機能に必要なフォント・画像を外部取得しない。動きは状態把握に不可欠なものだけとし、OS の動きを減らす設定を尊重する。

## 実装時の UI / 推論契約

- UI は現在のモデル取得状態と翻訳セッション状態の両方を見て操作可否を決める。取得・検証中にロードや推論を始めるなどの競合を防ぐ。
- UI は翻訳元言語、翻訳先言語、入力文、最大長を明示して推論層へ渡す。必要に応じて既存の `TranslationSession` API を更新し、日本語 → 英語と英語 → 日本語をモデルの実際の能力に合わせて扱う。モデルキャッシュやリースの意味を UI から変更しない。
- 実行設定は設定値として表示し、実際に選択された backend の状態が推論層から得られない限り「GPU 使用中」とは表示しない。
- model/download/error の回復操作は UI 状態から導出し、ボタンの有効・無効と近くの説明を常に一致させる。

## 実装後の確認項目

- 320 / 768 / 1280 px で、視線が言語方向 → 入力と翻訳 → 結果に進み、主要操作が最初の画面内で見つかること。320 px で横スクロールしないこと。
- モデル未取得、保存済み未ロード、準備完了、取得中、中止中、推論中、ロード解除中、エラー、空出力、途中出力、コピー失敗の状態で、次の操作とその理由が表示されること。
- キーボードだけで言語変更、swap、入力例、消去・undo、翻訳、cancel、copy、モデル設定を操作でき、focus が見失われないこと。
- 言語方向と backend の設定が再起動後に復元され、無効な値や storage 失敗で既定値に戻っても翻訳が継続できること。入力・結果は再起動後に復元されないこと。
- オフライン準備の完了条件、初回 reload、明示更新、別タブ時の削除制御、部分資産欠損時の復旧を確認する。実ブラウザーでのオフライン動作は[設計書の未確認範囲](offline-and-preferences.md#確認項目と未確認範囲)として利用者の手動確認まで未検証とする。
- 入力と方向の変更で古い結果が消え、新しい翻訳の開始でも古い結果が消える一方、ロード解除後に入力と有効な結果は残ること。
- ダウンロード、推論、コピーについて誤った成功表示がなく、設定と実際の GPU 利用を混同させないこと。
- ブラウザー操作による自動化はこのリポジトリの制約で行わない。ソースとモックテストによる状態確認に加え、利用者が実ブラウザーで手動確認する項目を残す。

## 追加機能の設計: 逐次表示・長文翻訳・実行環境

### 逐次表示

- 推論層から届いた生成テキストを出力欄へ順次追加する。開始時に前の結果を消し、最初のテキストを受信する前は「翻訳中」と示す。生成中の文章は暫定結果として扱い、完了するまでコピー操作を無効にする。
- 結果欄は `aria-busy="true"` にし、処理状態だけを簡潔にライブ通知する。トークンごとに変わる本文をライブ領域にしない。これにより支援技術が文章全体を毎回読み上げるのを防ぐ。完了後も結果に自動フォーカスを移さない。
- 中止・エラー・出力上限に達したときは、受信済みの文章を残し、「未完了」「途中まで」と状態を明示する。中止後はモデルがロード解除されている場合があるため、再開前に必要な準備操作を示す。完了した結果だけを通常の翻訳完了として扱う。
- 新しい入力、言語方向、翻訳実行は古いストリームを無効にする。終了済み・古い処理から遅れて届いた通知は、表示にも進捗にも反映しない。

### 長文の分割翻訳

- 入力上限は 10,000 UTF-16 コード単位とする。入力欄の文字数と補助文で上限を示し、上限超過を推論開始前に拒否する。値は画面だけでなく翻訳セッションでも検証する。
- 分割幅は正確なトークン数ではなく、固定された PLaMo 3 tokenizer の性質から得る保守的な上界で決める。PFML のプロンプト全体を UTF-8 にした byteLength に BOS 1 token を足し、出力予約 512 token と合わせて contextSize 2048 以下となるチャンクを計画する。`getTranslationBudget(request)` は `inputTokenUpperBound`、`contextSize`、`maxOutputTokens`、`method: 'utf8-upper-bound'`、`fits` を返す。モデルの特殊文字列や翻訳方向を含む完成済みプロンプト全体を評価する。
- PLaMo 3 の固定 tokenizer では、通常 token は Unicode code point 以上の入力を消費し、unknown piece は UTF-8 byte fallback へ進むため、プロンプトの UTF-8 byteLength は入力 token 数の安全側上界になる。この上界は実トークン数ではないので、実行時表示で「計測したトークン数」と呼ばない。安全余裕を取るため実際より短いチャンクに分かれる場合がある。[固定版 llama.cpp の PLaMo 3 tokenizer](https://github.com/ggml-org/llama.cpp/blob/d38bea34227bbf9069d62fdc239c98ab6e05435a/src/llama-vocab.cpp#L1499) がこの上界の根拠。
- 固定モデル、tokenizer、normalization 方針との互換性を推論アダプターで検証する。前提を確認できない場合は分割翻訳を fail closed で拒否する。モデルや engine を更新するときはこの上界が保たれるかを再確認する。
- 長文は段落境界、文末境界、空白境界の順に優先して連続した部分へ分ける。境界だけでは上限に収まらないときは単語境界、最後に Unicode コードポイント境界で分け、サロゲートペアの途中では切らない。分割位置で取り出した改行・区切りはチャンク間の separator として保持して結果の連結に使う。生成結果内のすべての改行位置までは保証しない。1コードポイントでも許容 token 上界を超える入力は、無限分割を試みず説明付きで拒否する。
- 実際に分割している間は「文章を分けて準備しています」と表示し、総数を数え終わる前に架空の進捗率を出さない。分割後は「翻訳中 2 / 5」のように完了単位数を示す。所要時間は推定しない。
- 文脈を分けることで段落や文のつながりが弱まる場合があることを、長文翻訳の開始前に短く案内する。最初から画面を説明文で埋めない。
- 完了した部分、現在の部分、未着手の部分を区別する。失敗・中止・出力上限・空出力では途中結果を保ち、「翻訳が完了していない」と表示する。失敗した部分を含むそれ以降だけが未完了であることを示し、「未完了の箇所から再開」を提供する。再開では完了済み部分を再生成しない。中断した部分の部分出力は再開時に置き換える。停止後の部分結果はコピーできる。
- 再開データは現在のページのメモリにだけ保持し、`resumeTranslation(text, direction)` に渡した入力と方向が中断時の snapshot に一致する場合に限って利用する。入力または方向を編集したら部分結果・再開情報を破棄し、通常の設計どおり新しい翻訳として扱う。ロード解除だけでは部分結果と再開情報を消さない。中止でモデルが解除された後の再開では、モデルのロードが必要なことを先に示し、利用者が準備した後に再開操作を選べるようにする。
- 再ロード後に実効 context size が小さくなって未完了部分が現在の budget に収まらない場合、完了済みの prefix を残し、未完了 suffix だけを現在の上界で再分割する。出力上限に達した部分はそれより短い chunk に分けて再試行する。さらに分割できない場合は入力を手動で短くする案内を出す。
- 生成中は中止ボタンを提供し、停止とリソース解放が終わるまで「中止しています」と伝える。再開を始めたら前回の暫定テキストを同じ部分の新しい出力で置き換え、二重に連結しない。

### 実行環境の表示

- 利用者が選んだ「自動選択（WebGPU 優先）」または「CPU（WASM）」を要求設定として表示し、ロード後に推論 API の `runtimeInfo` を別項目として示す。
- 自動選択では wllama が実際の GPU レイヤー配置を公開しないため、`backend: unknown` を「確認できません」と表示する。ブラウザーの GPU 対応有無や要求設定から推測しない。CPU 要求は `n_gpu_layers=0` と Worker の `noWebGPU=true` を適用した場合に CPU と表示する。
- `webGpuApiAvailable` が取得できた場合は WebGPU API の有無として示す。この値は GPU が実際に選ばれた証拠として扱わない。
- `runtimeInfo` には要求 context size と実際の context size、取得元を含める。GPU 名や GPU レイヤー数は確かな値が API から返されない限り表示しない。要求設定、実際の backend、context size の根拠は折りたたみ式モデル設定にまとめる。

### 共通の状態・アクセシビリティ

- session の `translationProgress` は `planning` または `translating` を示し、`completed` と任意の `total` を持つ。総数が決まる前は「文章を分けて準備しています」とし、分割後は `n / m` を表示する。残り時間は推定しない。
- 結果は `streaming`、`partial`、`complete` のいずれかで、部分結果には `cancelled`、`error`、`truncated`、`empty` の理由を示す。`canResume` が true のときだけ「未完了の箇所から再開」を提供する。状態名と進捗の更新だけをライブ通知し、結果本文の逐次通知は行わない。
- 中止、失敗、空出力、上限到達では、起きたことと次に取れる操作を結果の近くに示す。再開・ロード・入力修正のどれが必要かを明確にし、失敗した表示のまま翻訳ボタンだけを無効化しない。
- キーボードフォーカス、見えるラベル、44×44 px の操作領域、レスポンシブ配置とコントラストは既存要件を継承する。狭い画面でも進捗、部分結果、再開操作の関係が分かる順に並べる。
- モックテストでは分割境界、進捗、古い通知の破棄、再開時の完了部分保持、キャンセル後の再ロード、実行環境の不明状態を確認する。ブラウザーの実モデル確認は自動化せず、ストリーミング表示、長文の複数分割、中止・再開、実行環境表示を利用者が手動確認する。これらの新機能は確認前に実モデル動作済みと記載しない。
