状態: 取得済みモデルと推論 API を接続する画面を実装し、模擬エンジンで操作フローを検証済み。
利用者の手動検証で実モデルのロード・1 文翻訳が成功。
利用者が GPU（auto 設定）・CPU（WASM）の両経路で翻訳とロード解除を確認済み。
エージェントによるブラウザ操作は行っていない。

## 手動検証の結果

2026-11-07、利用者から翻訳ができたとの報告を受領。出力は次のとおり。

```text
The meeting has been rescheduled for next Monday.
```

最初の成功条件である、PLaMo 3 Translate 0.8B によるブラウザ内の日本語1文→英語の翻訳を
利用者の環境で確認できた。その後、GPU と CPU（WASM）の両方が動作したとの報告とログを受領。

| 経路 | ロード | 翻訳 | 上限到達 | ロード解除 |
| --- | --- | --- | --- | --- |
| GPU（要求設定 auto、利用者確認） | 1,757 ms | 359 ms | なし | 完了 |
| CPU / WASM（要求設定 cpu） | 1,613 ms | 2,380 ms | なし | 完了 |

共通設定は contextSize=2048、threads=1、ja→en、maxTokens=512。
日本時間の2026-11-07 00:18〜00:19に実行された [利用者提供ログ](validation/2026-11-07-translation.log) を保存した。
ログの時刻は UTC。両経路とも ready に戻り、truncated=false、dispose 完了を確認できる。
値は単発の UI 計測で、一般的な性能や厳密なベンチマークを示さない。

GPU 動作の確認は利用者からの報告に基づく。auto と記録されたアプリログだけでは GPU 使用を判定しない。
実際の入力文、ブラウザ・OS・端末・GPU 名、メモリ使用量、個別の停止理由は未記録。
truncated=false により上限未到達は確認できるが、どの停止トークンで終了したかは区別できない。
この結果を、すべてのブラウザ・端末で動作する証拠とは扱わない。

## 操作手順

1. npm run dev を実行し、/local-web-translation/ を開く。
2. 「モデルを取得」で固定版を取得する。検証成功後に「モデルをロード」が有効になる。
3. 実行設定を選び、「モデルをロード」を押す。モデルの再ダウンロードは行わず、
   ページ内の取得済み Blob を推論 API に渡す。
4. 日本語の例文を確認し、「英語へ翻訳」を押す。入力は500文字まで編集できる。
5. 英語の出力・翻訳処理時間・検証ログを確認する。
6. 設定を変えて比較する場合は「ロードを解除」し、別の設定を選んで再ロードする。

初期入力は「会議は来週の月曜日に変更されました。」。
翻訳要求は sourceLanguage: ja、targetLanguage: en、maxTokens: 512。
PFML3、BOS、停止条件は [推論 API](inference-api.md) の設定を使用する。
出力の一致をハードコードして成功判定しない。実行結果の内容は手動で確認する。

## 実行設定

| 画面の選択肢 | 要求する設定 |
| --- | --- |
| 自動選択（WebGPU 優先） | backend: auto |
| CPU（WASM） | backend: cpu / n_gpu_layers: 0 |

contextSize は 2048、threads は 1。表示・ログは要求設定を示し、実際に GPU を使用した証拠ではない。
GPU / CPU の比較や性能評価は、この画面で手動実行した結果と実行環境を記録して行う。
利用者は GPU / CPU の動作を確認済み。アプリ自身による使用バックエンドの検出表示と、メモリ使用量の計測は未実装。

## 状態・結果・復旧

- モデルのロード前は翻訳ボタンを無効にする。実行中の重複操作や、ロード済み状態での設定変更を防ぐ。
- ロード・翻訳・中止・解除の状態を role=status、失敗を role=alert で表示する。
  同じ状態文言をログ更新のたびにライブ通知しない。
- 実行中は入力を読み取り専用にする。編集時・再実行時・ロード解除時は以前の結果を消去する。
- トークン上限に達した出力は未完の可能性を明示する。空の出力も完了した翻訳とは扱わない。
- モデル出力やエラーは textContent で描画し、HTML として解釈しない。
- 「処理を中止」はエンジンの abort を呼ぶ。ネイティブ処理の終了と解放を待つため、即時停止は保証しない。
  中止後はモデルを再ロードする。ダウンロード済み Blob は保持する。
- 「ロードを解除」は dispose の完了を待つ。失敗時はエラーを表示し、解除を再試行できる。
- モデルを使っている間はダウンロード画面のモデル削除を無効にする。他タブからの削除も使用リースで待機する。
  ロード解除成功後に削除できる。解除に失敗している間は削除操作を有効に戻さない。

既定の OPFS 保存を選ぶと、ページの再読み込み後もキャッシュを検証して利用できる。メモリ保存を選んだ場合はページの再読み込み・終了で取得データが失われる。OPFS 実ブラウザー検証の状況は[モデルキャッシュ文書](model-cache.md)を参照。

## 検証ログ

直近100件の要求設定、状態変化、ロード・翻訳時間、上限到達の有無、エラーと原因をページ内に表示する。
時刻は ISO 8601 の UTC。成功時の原文・訳文をログへ自動追加せず、外部にも送信しない。
エラー原因に実行エンジンのメッセージが含まれる場合があるため、共有するときは内容を確認する。

手動検証では以下を記録する。

- ブラウザ・バージョン、OS、端末、要求設定。
- ロードが完了したか、英語の出力、空出力・上限到達・エラーの有無。
- 翻訳処理時間と検証ログ。表示時間は UI からの要求全体であり、厳密なベンチマークではない。
- 中止・再ロード・ロード解除・メモリ削除の挙動。

## 実装と自動検証

| ファイル | 責務 |
| --- | --- |
| src/poc/translation-session.ts | モデルの受け渡し、推論 API 呼び出し、結果・時間・ログの保持 |
| src/ui/translation-view.ts | 操作可否と状態文言の決定 |

| src/ui/model-download.ts | 取得・削除操作と、使用中モデルの削除ロック |
| tests/translation-session.test.mjs | 模擬モデル・エンジンによる操作フローと表示状態の確認 |

自動テストは未取得時の操作禁止、Blob の受け渡し、日英方向、同時実行の制御、中止・再ロード、
エラー原因表示、解除失敗後のロック、空出力・上限到達、ログ上限を確認する。
ブラウザの描画・キーボード操作や、実 WASM の初期化・推論を検証したものではない。
